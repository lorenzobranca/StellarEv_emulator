StellarEv emulator: speed-up over YREC / rotevol
=================================================
Date: 2026-09-11
Host: compgpu8 (AMD EPYC 7452 32-core CPU, NVIDIA A100-PCIE-40GB GPU)
Software: Python 3.12.3, JAX 0.11.0, Flax 0.12.8
Benchmark script: bench_emulator.py (repo root), usage `python bench_emulator.py [gpu|cpu] [log|diff]`
Checkpoints: Zenodo record 19736519, checkpoints_new.zip (md5 41079a40ed7e61d3fe936312574ad2e8)


1. Reference runtimes (from collaborator)
-----------------------------------------
Solar-mass star, stopping condition: central hydrogen fraction < 1e-3, reached at 9.5 Gyr.

  Non-rotating YREC evolution track ........ 100.233 s
  rotevol post-processing on that track ....   0.152 s
  Total, non-rotating track + rotevol ...... 100.385 s

  Full YREC model with rotation ............ 142.004 s


2. Emulator measurements
------------------------
Initial conditions: Mstar = 1.0, [Fe/H] = 0.0, PMMA = 1.5, PMMB = 2.1, PMMM = 0.3.
Each prediction returns the full trajectory of all 7 observables (logTeff, Prot,
Bcoronal, Patm, tau_cz, dM/dt, luminosity) on the 3999-point pseudo-time grid plus
the age axis, i.e. the whole track out to ~13 Gyr, not only up to 9.5 Gyr.

"Default predictor" = CombinedPredictor.predict() from make_inferences_{log,diff}.py.
Since 2026-09-11 the two network forward passes are wrapped in jax.jit at load time
(TimeModelPredictor.forward / OutputModelPredictor.forward); the rest of predict()
(conversion to NumPy, SciPy interpolation for age queries) is unchanged. Jitted and
eager outputs agree to <5e-6 in scaled units. Timings are medians over 50 (GPU) or
20 (CPU) repeated calls after a warm-up call. Model loading (~5-7 s) and first-call
compilation (~0.5-1 s) are one-off costs and are excluded.

Log variant (time model predicts log-age directly):

  mode                                         time / star
  single star, default predictor, GPU             3.1 ms
  single star, default predictor, CPU             7.5 ms
  single star + age query at 9.5 Gyr, GPU         3.5 ms
  batch of 100 stars, GPU                         0.21 ms
  batch of 1000 stars, GPU                        0.16 ms
  batch of 1000 stars, CPU                        0.33 ms
  NN forward only (both models), 1 star, GPU      0.71 ms
  NN forward only (both models), 1 star, CPU      6.6 ms

Diff variant (time model predicts delta-age, cumulative sum). Measured with the public
Zenodo time-diff checkpoint (latent 138, 7 layers, relu); a larger local retrain (latent 816,
8 layers, silu) gave the same timings within noise, so the time model is not the bottleneck:

  single star, default predictor, GPU             4.4 ms
  single star + age query at 9.5 Gyr, GPU         4.7 ms
  batch of 1000 stars, GPU                        0.19 ms
  NN forward only (both models), 1 star, GPU      0.87 ms

For reference, before jitting (predict() dispatching Flax ops one by one) a single
star took 194 ms (GPU) / 118 ms (CPU) for the log variant and 230 ms (GPU) for diff;
batched 1000-star inference took 0.47 ms/star (GPU). Jitting is therefore a ~60x gain
for single-star latency and ~3x for batched throughput.

Run-to-run variation on this shared node is about 10-30 %.


3. Speed-up factors
-------------------
Speed-up = reference runtime / emulator time per star.

  emulator mode (log variant)               vs 100.385 s     vs 142.004 s
  single star, default predictor, GPU             32,806 x         46,407 x
  single star, default predictor, CPU             13,474 x         19,061 x
  batch of 1000, per star, GPU                   626,232 x        885,864 x
  batch of 1000, per star, CPU                   306,988 x        434,263 x
  NN forward only, 1 star, GPU                   141,188 x        199,724 x

  emulator mode (diff variant, Zenodo checkpoint)
  single star, default predictor, GPU             22,815 x         32,274 x
  batch of 1000, per star, GPU                   538,257 x        761,416 x

  before jitting (log variant, for reference)
  single star, GPU                                   518 x            733 x

4. Suggested statements
-----------------------
  Latency (one star, default predictor, no batching):
    ~3e4 x faster than a non-rotating YREC track plus rotevol (GPU),
    ~4.5e4 x faster than a full rotating YREC model (GPU);
    ~1.3e4-1.9e4 x on CPU.

  Throughput (population studies, batched inference on GPU):
    ~6e5-9e5 x faster than either reference.

  Conservative round numbers: "four orders of magnitude" for single-star latency,
  "five to six orders of magnitude" for batched throughput.


5. Caveats
----------
- Single-star latency is now a mix of GPU kernel time (~0.7 ms for both networks),
  host transfer of the 3999 x 8 result, and NumPy/SciPy post-processing. The
  remaining overhead is in the un-jitted decode/interpolation code, not the networks.
- The reference runtimes were presumably measured on one CPU core. The emulator CPU
  numbers use the multi-threaded XLA CPU backend on a 32-core node, so the CPU-vs-CPU
  ratio is not strictly core-for-core.
- The emulator returns the complete track to ~13 Gyr; the reference runs stop at 9.5 Gyr.
  The comparison is therefore slightly conservative in the emulator's favour.
- The emulator also emits the rotation-dependent quantities (Prot, Bcoronal, dM/dt), so
  the fairer baseline is arguably the full rotating YREC model (142 s).
- jax.jit compiles once per distinct input batch shape; the first call for each new
  batch size costs ~0.5-1 s.


6. Sanity checks
----------------
Predicted age axis for the test star spans 1.7e-6 to 12.9 Gyr; the 9.5 Gyr query maps to
pseudo-time u = 0.37 and 4.57 Gyr to u = 0.15; scaled outputs have order-unity spread
across the track. The checkpoints under checkpoints_new/ were therefore loaded correctly.
